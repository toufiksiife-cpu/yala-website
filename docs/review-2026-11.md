# YALA public site — review, 10 Nov 2026

Live site: https://yala-website.toufik-siife.workers.dev
Pages checked: home, courses, register, about, contact, privacy, 404, 6 viewport widths (320/360/375/414/768/1024/1280).
Method: live DOM/CSS measurement, Lighthouse, network/console capture, keyboard + mobile-menu interaction, form validation.
Not done: no real registration was submitted (it would email staff and create a record); screenshots could not be captured
(the browser window was not visible), so every visual claim below is a measured number, not an opinion.

## Already good — do not touch

- Lighthouse 100/100/100 on home, courses, register, about, privacy (contact 98, see F3).
- Zero console errors, zero failed requests on all pages.
- 2 KB of HTML/CSS before images; 3 self-hosted Cairo files, 79 KB total, `font-display: swap`.
- Gallery images lazy-loaded, 378 KB total, width/height attributes present (no CLS).
- `prefers-reduced-motion` respected, `:focus-visible` present, skip link present and translated.
- Logical CSS properties (`margin-inline`), so RTL needs no extra rules.
- No prices anywhere in the public HTML or the public API.
- English pages contain no stray Arabic (only the language button label, which is correct).

## Findings, by impact

### F1 — Dead links land on a blank page (High)
`/nope-xyz` returns 404 with `<html><head></head><body></body></html>`: no title, no logo, no way back.
`404.html` exists but Cloudflare Workers static assets defaults to `not_found_handling: none`.
Effect: an old shared link or a typo ends the visit silently; Google sees an empty document.
Fix: add `wrangler.jsonc` with `assets: { directory: ".", not_found_handling: "404-page" }`.
Risk: this is the only change that touches deploy configuration; verify `/` and one deep link after deploy.

### F2 — Choosing a course is the hardest step on the site (High)
Register page on a 375 px phone: 25 checkboxes in a 2,950 px list, page 5,640 px, submit button 4,861 px down.
Category headings are Arabic; course names come from the Sheet in English (`French`, `Lecture`, `1AM-2AM`).
Fix (no Sheet change): a filter box above the picker (matches Arabic category + English name) and native
`<details>` per category so the list starts collapsed. Target: one screen before expanding.

### F3 — Contact page skips a heading level (High, cheap)
`h1` → `h3` ("العنوان", "أوقات العمل") → `h2`. Lighthouse accessibility 98, only failure `heading-order`.
Fix: make those two `h3` into `h2` (they are top-level sections, not sub-points).

### F4 — Form fields and the focus ring are too faint (High, invisible until tested)
Measured on white: input border `#C7D0DC` = **1.56:1**, focus ring `#F18225` = **2.64:1**. WCAG 1.4.11 needs 3:1.
On a phone in daylight the fields read as empty space and the focus ring is nearly lost.
Fix: input border `#7A869A` (3.68:1), focus outline `var(--navy)` (9.83:1) or `#B35F12`.

### F5 — Mobile header is overfull (High, visual)
`.nav-cta { display: none }` is overridden by `.btn { display: inline-flex }` later in the stylesheet, so the
orange CTA shows at every width. At 320 px the logo shrinks to 50 px wide and the button is 58 px tall in a 65 px bar.
Fix: `@media (max-width: 759px) { .nav-cta { display: none; } }` (it is already in the menu), or shrink the button
and give the logo a `min-width`. Choose one; do not do both.

### F6 — Courses page is a 6,569 px scroll with no wayfinding (Medium)
25 cards, 6 sections, 17 sub-sections, no anchors, cards not clickable, no per-course way into registration.
Fix: ids on the six section blocks + a row of chips that jump to them. Then (optional) `register?course=<full>`
preselects a course from a card.

### F7 — Mobile menu only closes with the same button (Medium)
No Escape handler, no outside-tap close, no focus return; tabbing leaves the open panel.
Fix: ~8 lines in `app.js` (Escape, outside click, refocus button).

### F8 — Footer tap targets are 26–34 px (Medium)
Phone 30, WhatsApp/social 34, privacy 26. Recommended minimum is 44.
Fix: `padding-block: 12px` on footer links and social links.

### F9 — Arabic text carries Latin letter-spacing (Medium, typography)
`.hero .kicker` 0.544 px, `.site-footer h3` 1.152 px. Letter-spacing breaks Arabic joins, and `text-transform: uppercase` is a no-op.
Fix: `html[dir="rtl"] .hero .kicker, html[dir="rtl"] .site-footer h3 { letter-spacing: 0; }`

### F10 — Heading line-height is body line-height (Medium, typography)
h2 30.4 px on 50.16 px (1.65), h3 20 on 33 (1.65). Two-line headings look disconnected.
Fix: `h1,h2,h3 { line-height: 1.25; }` — one rule, no size changes.

### F11 — Language button has no accessible name (Medium, a11y)
Screen reader hears "EN" / "العربية" only.
Fix: `aria-label` translated via `i18n-aria` ("Change language").

### F12 — Errors are one box, not per field (Medium)
`#form-error` is `role=alert` (good) and focus moves to the first bad field (good), but the field gets no
`aria-invalid` and no inline message.
Fix: set `aria-invalid` + one `.field-error` line under the field.

### Low
- No type scale: 13.6 / 15.2 / 16.8 / 30.4 px are em-derived accidents. Snap to 14 / 15 / 17 / 30 in the tokens.
- `fonts.css` declares `font-style: normal` twice in all 9 `@font-face` blocks (copy-paste tell, harmless).
- `dob` has no `autocomplete="bday"`.
- Home has no proof (years, number of teachers/students) and no FAQ. Both need real content from the school, not code.

## Suggested order

Phase A (safe, no data changes): F3, F4, F5, F7, F8, F9, F10, F11 — CSS + a few attributes.
Phase B (one feature): F2 course picker filter + collapsible sections.
Phase C (needs a decision): F1 404 (deploy config), F6 section chips, F12 field errors.
Phase D (needs content from the school): proof numbers, FAQ, Arabic course names in the Sheet.
